# 🗺️ Roadmap

This roadmap distinguishes practical work on the current static site from larger service ideas that require separate product and security decisions. Priorities may change as requirements are validated.

- [ ] Correct page resource references and local asset paths.
- [ ] Align service-tab controls with their actual panel IDs.
- [ ] Add accessible keyboard behavior and selected-state announcements.
- [ ] Correct malformed HTML and missing navigation targets.
- [ ] Decide whether to remove the placeholder contact form or connect a real handler.
- [ ] Complete responsive, keyboard, and browser verification.
- [ ] Capture genuine desktop/mobile screenshots after UI defects are resolved.

## 🟡 Engineering quality

- [x] Add project-specific documentation and Mermaid source diagrams.

- [x] Add baseline static validation workflow.
- [x] Add dependency audit workflow.
- [ ] Add reliable HTML and local-link validation.

## 🔵 Service integration, only after approval

- [ ] Define the actual contact/lead workflow and data minimization.
- [ ] Select a supported backend or managed form service.
- [ ] Implement server-side validation, rate limiting, spam controls, and privacy disclosures.
- [ ] Define retention, deletion, access control, and incident response.

## 🟣 Longer-term product possibilities

- [ ] Evaluate booking integration against real user needs.
- [ ] Evaluate AI consultation integration with a server-side provider boundary.
- [ ] Define model safety, quality evaluation, cost, and fallback behavior before launch.
- [ ] Add accounts or dashboards only if there is a clear requirement and operational owner.

## Prioritization

Each roadmap item should have an owner, problem statement, acceptance criteria, dependencies, and risk assessment. A checkbox is not evidence of completion; update it only after the implementation is merged and verified.
